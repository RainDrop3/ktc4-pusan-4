## 한 일

- **`RUN_START_FAILED` 문구** — #128 이 run 을 시작하지 못하면 대상 거래 전체를 이 코드로 끝낸다(api.md 3.6). 실패 목록에 「시작 실패 · 판정을 시작하지 못했습니다. 다시 실행해 주세요.」가 뜬다. 전에는 모르는 코드라 「처리하지 못했습니다」였다
  - 목 `failNextRun(count, code)` 이 실패 코드를 받는다. 기본은 전처럼 `RULE_PROCESSING_FAILED`
- **분류 확인 409** — 다른 곳에서 먼저 분류했으면 `409 CLASSIFICATION_ALREADY_RESOLVED` 다(#158). 서버 문장을 띄우고 카드를 남기던 것을, 「이미 분류한 가맹점입니다. 목록을 다시 불러왔습니다.」를 띄우고 다시 읽게 했다
- **목의 질문 거르기** — 판정대상만 보던 것을 현재 결과와 같은 조건(판정대상 + 분류 완료)으로 거른다. #134 에서 yuyeol3 이 이 조건으로 정했다
- **미분류 거래를 다시 포함할 때 안내** — 「판정을 새로 실행해야」 대신 「분류 확인을 마친 뒤 판정을 새로 실행해야」와 분류 확인 버튼을 띄운다. 한 번이라도 미분류를 넣었으면 그 안내가 남는다

## 왜 이렇게 했나

- 미분류 안내를 따로 둔 것: run 은 미분류 거래를 엔진에 넘기지 않는다. #148 은 미분류 거래를 다시 포함하면 분류 확인 항목을 만든다. 판정만 다시 돌리면 그 거래는 여전히 빠진다
- 목이 분류 확인 항목을 새로 만들지 않는 것: 미분류 픽스처는 모두 대기 중인 항목이 이미 있고, 목 업로드는 거래를 저장하지 않는다. 그 경로에 닿는 목 상태가 없어 만들어도 돌지 않는 코드다
- 질문 거르기 테스트를 따로 두지 않은 것: 목에서 질문이 붙은 거래를 미분류로 만들 API 가 없다. 거르는 조건은 이미 테스트가 있는 `isJudgeable` 하나로 바꿨다
